--------------------------------------------------
OBJETIVO
--------------------------------------------------
Conectarse por SSH desde la maquina host (Windows) a la VM Linux,
primero con usuario y contrasena y luego usando un par de llaves
(publica/privada) generado en Windows, para entrar sin contrasena.

--------------------------------------------------
1. VM EN MODO BRIDGE Y PRUEBA DE PING
--------------------------------------------------
VMware: Settings > Network Adapter > Bridged.

En la VM:
ip a
  -> Se anota la direccion inet de eth0 (192.168.x.x).

En Windows (PowerShell):
ping IP_DE_LA_VM
  -> Debe responder, lo que confirma que el host alcanza la VM.

--------------------------------------------------
2. HABILITAR SSH Y CONECTARSE CON USUARIO Y CONTRASENA
--------------------------------------------------
En la VM:
apt install openssh-server -y
  -> Instala el servidor SSH.
systemctl enable --now ssh
  -> Lo enciende y lo deja activo en cada arranque.
systemctl status ssh
  -> Debe decir active (running).

En Windows (PowerShell):
ssh elianny@IP_DE_LA_VM
  -> Pide la contrasena del usuario y abre una sesion en la VM.
exit
  -> Cierra la sesion.

(Se usa un usuario normal porque SSH no permite entrar como root con
contrasena por defecto.)

--------------------------------------------------
3. GENERAR EL PAR DE LLAVES EN WINDOWS
--------------------------------------------------
ssh-keygen -t ed25519
  -> Genera el par de llaves (tipo ed25519).
  Enter file in which to save the key:
     C:\Users\TU_USUARIO_WINDOWS\.ssh\id_ed25519
     (destino donde se guardan las llaves)
  Enter passphrase: (se deja en blanco, Enter)
  Enter same passphrase again: (en blanco, Enter)

Se crean dos archivos:
  - id_ed25519      -> llave privada (no se comparte).
  - id_ed25519.pub  -> llave publica (se copia al servidor).

dir $env:USERPROFILE\.ssh
  -> Muestra los dos archivos creados.

--------------------------------------------------
4. COPIAR LA LLAVE PUBLICA AL SERVIDOR
--------------------------------------------------
Desde Windows, se envia el archivo de la llave publica:
scp $env:USERPROFILE\.ssh\id_ed25519.pub elianny@IP_DE_LA_VM:/tmp/llave.pub

En la VM (conectado con ssh elianny@IP_DE_LA_VM, con contrasena):
mkdir -p ~/.ssh
chmod 700 ~/.ssh
cat /tmp/llave.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
rm /tmp/llave.pub
exit
  -> authorized_keys guarda las llaves publicas autorizadas a entrar.
  -> chmod 700 y 600 dejan los permisos que SSH exige.

--------------------------------------------------
5. PRUEBA: ENTRAR SIN CONTRASENA
--------------------------------------------------
En Windows (PowerShell):
ssh elianny@IP_DE_LA_VM
  -> Entra automaticamente, sin pedir contrasena, usando la llave.

Si las llaves se guardaron en otra ruta distinta a .ssh\id_ed25519:
ssh -i RUTA_DE_LA_LLAVE_PRIVADA elianny@IP_DE_LA_VM

Si todavia pide contrasena, se revisan los permisos en la VM:
ls -ld ~ ~/.ssh ~/.ssh/authorized_keys

--------------------------------------------------
RESULTADO
--------------------------------------------------
Acceso por SSH desde Windows con usuario y contrasena, y luego con
llaves, entrando de forma automatica sin solicitar credenciales.
